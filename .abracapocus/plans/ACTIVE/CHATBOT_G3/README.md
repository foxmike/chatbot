# CHATBOT

## Purpose

Group 3 of the companion buildout, run after Group 2 (phases l, m, n) is accepted. This group gives the companion agency, scene-based interaction, and multi-user readiness. Phase O adds proactivity: a scheduler that decides when to initiate using rituals, timeline, and per-user initiative settings; proactive check-in generation grounded in recent context; a notifications model and pollable delivery queue (reminders, emotional check-ins, continuation prompts, milestone and event callbacks); and initiative controls (never proactive, reminders only, gentle check-ins, frequent, high-energy). Phase P adds a roleplay and room model: a scene state engine (location, activity, tone, intensity, pause/resume), roleplay memory isolation so scene content does not pollute durable factual memory unless explicitly marked, and typed rooms (one-on-one chat, roleplay scene, project room, emotional support room, memory review room) with per-room memory policy. Phase Q makes the system deployable to real users: authentication, per-user data isolation formalizing the user_id partition that was deferred at schema time, and multiple companions per user with private per-companion memory and optional shared room memory. All work lands inside the existing chatbot package and react_ui frontend; the stack is unchanged. Background scheduling reuses the consolidation-worker pattern from phase f.
