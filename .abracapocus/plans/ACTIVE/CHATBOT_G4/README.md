# CHATBOT

## Purpose

Group 4 of the companion buildout, run after Group 3 (phases o, p, q) is accepted. This group adds modalities and production operations. Phase R adds voice: a TTS/STT provider interface mirroring the existing LLM Provider pattern, a TTS adapter with emotional cadence driven by the phase-K mood/mode state, an STT adapter for voice input, and a call/phone mode. Phase S adds visual identity: an image-generation and image-understanding provider interface, generation with an appearance/character seed lock for visual continuity, customizable appearance and outfit continuity, event-based images that become image memories in shared history, and multimodal image understanding for user-sent images. Phase T adds observability and intelligent routing: per-turn tracing (prompt, retrieval, routing, latency), structured logs (memory-write, contradiction, failed-retrieval), latency/token/cost metering, an admin dashboard, and a task-class-aware extension of the provider policy router (casual vs emotional vs summarize vs extract vs embed). Phase U adds latency and scale: token streaming with typing indicators and partial generation, background async processing to move memory extraction and consolidation off the response path, cached persona context, and short-response mode — directly targeting the cold-start latency observed in early testing. All work lands inside the existing chatbot package and react_ui frontend; modality providers follow the same exact-identifier validation discipline as the LLM providers.
